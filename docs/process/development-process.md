# Development Process: Taakht Project

Decisions about the team's way of working (a team of two). Architecture decisions are in `architecture-decisions-log.md` and `architecture-overview.md`.

## Methodology
- **Scrum** (final, 1405/07/02). There was resistance at first, but it was chosen to give the work structure and to get decisions documented. Not every Scrum component is needed for a team of two.
- **Planning:** weekly at first, later every two weeks.
- **Retrospective:** at the end of each sprint, together with the Planning meeting.
- **Daily Standup:** none (cancelled).

## Tools and work tracking
- Platform: **GitHub**, for issue tracking and pull/merge requests.
- Tasks are linked to an **Epic** and get **Story Points**.
- **Milestones** are used; for now open, without an exact time-box.
- After development, each task is linked to a merge request and **the other person does a code review**.

## Git workflow
- **History is linear: we rebase, we do not merge.** Keep a branch up to date by rebasing it onto `main`; never merge `main` into a branch. A branch that has merge commits fails CI.
- **PRs are merged with "Rebase and merge".** Each commit lands on `main` exactly as written, so every commit has a Conventional Commits message, passes the hooks, and has no fixup noise. Clean the branch up before asking for review (squash fixups, reword).
- **Settings:** the repository allows only "Rebase and merge" (merge commits and squash are disabled) and requires the `ci-ok` check. This is a GitHub setting, not something the repo enforces by itself.
- **Force-push** a feature branch after rebasing, with `--force-with-lease`. Do not force-push `main`, except to repair history when both people agree.

## Testing
- Unit + integration (mandatory) + end-to-end.
- TDD: a pilot on some services, not everywhere.
- Load and stress tests: scripts live in the repository; results are kept both as log records and on an overview page. Details: `architecture-overview.md`, section 7.

## AI-generated files
- Tools and files generated by AI are kept in a dedicated directory inside the repository.
- Open: whether the name/structure of this directory should depend on the agent (like `.claude` or `.gemini`). Alireza prefers a clean, uncluttered structure.
